## 概要

本ドキュメントでは、Amazon S3 Tablesに関するよくある質問と回答をまとめています。

---

## 基本的な質問

### Q1: S3 Tablesとは何ですか？

**A**: Amazon S3 Tablesは、Apache Icebergテーブルフォーマットを使用した、分析ワークロード専用のストレージサービスです。自動メンテナンス、高いTPS、AWS分析サービスとのシームレスな統合を提供します。

### Q2: S3汎用バケットとの違いは何ですか？

**A**: 主な違いは以下の通りです：
- **自動メンテナンス**: コンパクション、スナップショット管理が自動
- **高パフォーマンス**: テーブルワークロードに最適化されたTPS
- **専用ネームスペース**: s3tablesネームスペースで独立したアクセス制御
- **常時プライベート**: Block Public Accessが常に有効

### Q3: 既存のIcebergテーブルをS3 Tablesに移行できますか？

**A**: はい、可能です。ただし、In-place Migrationは使用できず、Full Data Migrationが必要です。以下の方法があります：
- CTAS（CREATE TABLE AS SELECT）
- Sparkプログラマティック移行
- AWS Glue ETLジョブ

詳細は[データレイク移行](../05-advanced/03-migration-from-datalake.md)を参照してください。

## 機能に関する質問

### Q4: どのクエリエンジンがサポートされていますか？

**A**: 以下のクエリエンジンがサポートされています：
- Amazon Athena
- Amazon Redshift（Spectrum経由）
- Apache Spark（EMR、Glue、EMR Serverless）
- Presto/Trino
- PyIceberg

### Q5: リアルタイムデータ取り込みは可能ですか？

**A**: はい、Amazon Data Firehoseを使用してリアルタイムデータ取り込みが可能です。以下のソースがサポートされています：
- Amazon Kinesis Data Streams
- Amazon MSK
- AWS IoT Core
- CloudWatch Logs
- Direct PUT（SDK/API）

### Q6: マルチリージョン展開は可能ですか？

**A**: S3 Tablesは現在シングルリージョンサービスですが、以下の方法でマルチリージョン展開が可能です：
- Sparkによるクロスリージョンレプリケーション
- アクティブ-パッシブ構成
- アクティブ-アクティブ構成（双方向レプリケーション）

詳細は[マルチリージョン戦略](../05-advanced/01-multi-region-strategy.md)を参照してください。

## 制限事項に関する質問

### Q7: カラム名に大文字を使用できますか？

**A**: いいえ、推奨されません。S3 Tablesは混合ケース（大文字と小文字の混在）をサポートしていません。すべて小文字のカラム名を使用してください。

```sql
-- ❌ 非推奨
CREATE TABLE my_table (UserId INT, UserName STRING);

-- ✅ 推奨
CREATE TABLE my_table (user_id INT, user_name STRING);
```

### Q8: Table Bucketの数に制限はありますか？

**A**: はい、デフォルトでリージョンごとに10個までです。ただし、AWSサポートに連絡することで引き上げ可能です。

### Q9: パブリックアクセスは可能ですか？

**A**: いいえ、S3 TablesはBlock Public Accessが常に有効で、無効化できません。すべてのTable BucketとTableは常にプライベートです。

## パフォーマンスに関する質問

### Q10: クエリパフォーマンスを向上させるには？

**A**: 以下の方法があります：
- **パーティショニング**: 適切なパーティションキーの選択
- **コンパクション**: 小ファイルの統合
- **Z-Ordering**: 頻繁にフィルタされるカラムでソート
- **カラムプルーニング**: 必要なカラムのみ選択

詳細は[パフォーマンス最適化](../02-operations/02-performance-optimization.md)を参照してください。

### Q11: 自動メンテナンスの頻度は？

**A**: 自動メンテナンスは以下の頻度で実行されます：
- **コンパクション**: 定期的（設定可能）
- **スナップショット管理**: 保持ポリシーに基づく
- **未参照ファイル削除**: 設定された期間後

### Q12: 大量データの書き込みパフォーマンスは？

**A**: S3 Tablesは高TPSを提供しますが、以下の点に注意してください：
- Firehoseスループット制限（主要リージョン: 5 MiB/秒、その他: 1 MiB/秒）
- AppendOnlyフラグで自動スケール可能
- Sparkによる並列書き込みで高スループット実現

## コストに関する質問

### Q13: 料金体系は？

**A**: S3 Tablesの料金は以下で構成されます：
- **ストレージ料金**: 保存データ量に基づく
- **リクエスト料金**: API呼び出し回数に基づく
- **メンテナンス料金**: 自動メンテナンス操作に基づく

詳細は[料金](../01-getting-started/03-pricing.md)を参照してください。

### Q14: コストを最適化するには？

**A**: 以下の方法があります：
- **データ圧縮**: Parquet + Snappy/Zstd
- **パーティション最適化**: 過度なパーティショニングを避ける
- **ライフサイクル管理**: 古いデータのアーカイブ/削除
- **クエリ最適化**: 不要なスキャンを削減

## セキュリティに関する質問

### Q15: データは暗号化されますか？

**A**: はい、以下の暗号化がサポートされています：
- **保存時**: SSE-S3（デフォルト）、SSE-KMS
- **転送時**: HTTPS必須（HTTP非サポート）

### Q16: きめ細かいアクセス制御は可能ですか？

**A**: はい、AWS Lake Formationを使用して以下のレベルでアクセス制御が可能です：
- データベースレベル
- テーブルレベル
- カラムレベル
- 行レベル（データフィルタ）

### Q17: VPCエンドポイントは使用できますか？

**A**: はい、Gateway EndpointとInterface Endpointの両方がサポートされています。

## 統合に関する質問

### Q18: SageMakerと統合できますか？

**A**: はい、以下の方法で統合できます：
- SageMaker Feature Store（オフラインストア）
- SageMaker Training（学習データソース）
- SageMaker Lakehouse（統一データアクセス）
- Athena ML（SQL経由のML推論）

詳細は[機械学習統合](../04-integrations/04-machine-learning-integration.md)を参照してください。

### Q19: Redshiftと統合できますか？

**A**: はい、Redshift Spectrumを使用してS3 Tablesにアクセスできます。

```sql
CREATE EXTERNAL SCHEMA s3tables_schema
FROM DATA CATALOG
DATABASE 's3tablescatalog'
IAM_ROLE 'arn:aws:iam::123456789012:role/RedshiftSpectrumRole';

SELECT * FROM s3tables_schema.my_namespace.orders;
```

### Q20: QuickSightでビジュアライゼーションできますか？

**A**: はい、Athena経由でQuickSightからS3 Tablesにアクセスできます。

## トラブルシューティング

### Q21: テーブルが見つからないエラーが出ます

**A**: 以下を確認してください：
- カタログ設定が正しいか
- Namespace名が正しいか
- テーブル名が正しいか（すべて小文字）
- IAM/Lake Formation権限があるか

### Q22: Firehoseからのデータ配信が失敗します

**A**: 以下を確認してください：
- IAM権限（s3tables:PutTableData等）
- KMS権限（S3 Tables側で設定）
- スキーマの一致
- エラーバケットのログ

詳細は[トラブルシューティング](../02-operations/03-troubleshooting-guide.md)を参照してください。

## ベストプラクティス

### Q23: 推奨されるパーティション戦略は？

**A**: 以下のガイドラインに従ってください：
- カーディナリティが高すぎないカラムを選択
- クエリパターンに基づく選択
- 時系列データは日付でパーティション
- 過度なパーティショニングを避ける（目安: 1パーティション > 1GB）

### Q24: 推奨されるファイルサイズは？

**A**: 512MB（デフォルト）が推奨されます。以下の範囲で調整可能：
- 最小: 64MB
- 最大: 1GB
- 小ファイル問題を避けるため、定期的なコンパクションを実施

### Q25: データ品質を確保するには？

**A**: 以下の方法があります：
- AWS Glue Data Qualityでルール定義
- Sparkでのデータ検証
- スキーマ進化の適切な管理
- 定期的なデータ品質チェック
