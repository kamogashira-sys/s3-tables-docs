## 概要

Amazon S3 Tablesは、分析ワークロードに最適化されたS3ストレージを提供します。料金は使用した分だけ支払う従量課金制で、初期費用や最低料金はありません。

### 料金の特徴

- **ストレージ料金**: テーブルバケットに保存されているデータ量に基づく課金
- **リクエスト料金**: PUT、GET、LISTなどのAPI操作に基づく課金
- **オブジェクトモニタリング料金**: 保存されているオブジェクト数に基づく課金
- **メンテナンス料金**: 自動コンパクションと圧縮の処理に基づく課金
- **自動最適化**: テーブルバケットは継続的にメンテナンスを実行し、クエリ効率とストレージコストを自動的に最適化

## 料金体系の構成要素

Amazon S3 Tablesの料金は、以下の要素で構成されます。

### ストレージ料金

#### S3 Tables ストレージ

**概要**:
- クエリパフォーマンスが向上した分析ワークロード専用に最適化されたストレージ
- 保存されているデータ量（GB単位）に基づいて課金
- 階層型料金体系（使用量が増えるほど単価が下がる）

**料金（アジアパシフィック - 東京リージョン）**:

| ストレージ階層 | 料金（USD/GB/月） |
|--------------|------------------|
| 最初の 50 TB/月 | $0.0288 |
| 次の 450 TB/月 | $0.0276 |
| 500 TB/月以上 | $0.0265 |

**料金（米国西部 - オレゴンリージョン）**:

| ストレージ階層 | 料金（USD/GB/月） |
|--------------|------------------|
| 最初の 50 TB/月 | $0.0265 |
| 次の 450 TB/月 | $0.0254 |
| 500 TB/月以上 | $0.0244 |

**含まれるもの**:
- テーブルデータ（Parquet、Avro、ORCファイル）
- Icebergメタデータファイル（マニフェスト、スナップショット、統計情報）
- スナップショット（タイムトラベルクエリ用）

**コスト削減のポイント**:
- 自動メンテナンス（コンパクション、未参照ファイル削除）によるストレージ削減
- スナップショット保持ポリシーの最適化
- 不要なテーブルの定期的な削除

### リクエスト料金

#### S3 Tables リクエスト

**概要**:
- Table Bucket、Namespace、Tableに対するAPI操作に対する料金
- リクエストタイプによって料金が異なる

**料金（アジアパシフィック - 東京リージョン）**:

| リクエストタイプ | 料金（USD/1,000リクエスト） |
|-----------------|---------------------------|
| PUT、POST、LIST リクエスト | $0.0047 |
| GET、その他すべてのリクエスト | $0.00037 |

**料金（米国西部 - オレゴンリージョン）**:

| リクエストタイプ | 料金（USD/1,000リクエスト） |
|-----------------|---------------------------|
| PUT、POST、LIST リクエスト | $0.005 |
| GET、その他すべてのリクエスト | $0.0004 |

**リクエストの例**:
- **PUT/POST**: CreateTable、PutTableData、UpdateTable等
- **LIST**: ListTables、ListNamespaces等
- **GET**: GetTable、GetTableData等

**コスト削減のポイント**:
- 適切なパーティション設計によるスキャン範囲の削減
- ファイルプルーニングの活用
- クエリの最適化
- バッチ処理の活用

### オブジェクトモニタリング料金

#### S3 Tables オブジェクトモニタリング

**概要**:
- テーブルバケットに保存されているオブジェクトの監視に対する料金
- 保存されているオブジェクト数に基づいて課金

**料金（アジアパシフィック - 東京リージョン）**:

| 項目 | 料金 |
|------|------|
| モニタリング、全ストレージ/月 | $0.025/1,000オブジェクト |

**料金（米国西部 - オレゴンリージョン）**:

| 項目 | 料金 |
|------|------|
| モニタリング、全ストレージ/月 | $0.025/1,000オブジェクト |

**課金対象**:
- データファイル（Parquet、Avro、ORC）
- メタデータファイル（マニフェスト、スナップショット等）

**コスト削減のポイント**:
- コンパクションによるオブジェクト数の削減
- 適切なファイルサイズの設定（大きなファイルを作成してオブジェクト数を削減）
- 未参照ファイルの定期的な削除

### メンテナンス料金

#### S3 Tables メンテナンス

**概要**:
- S3が自動的に実行するメンテナンス操作に対する料金
- コンパクションと圧縮の2つの料金要素で構成

**料金（アジアパシフィック - 東京リージョン）**:

| メンテナンスタイプ | 料金 |
|------------------|------|
| コンパクション - オブジェクト† | $0.00185/1,000オブジェクト処理 |
| 圧縮 - データ処理量 | $0.005/GB処理 |

**料金（米国西部 - オレゴンリージョン）**:

| メンテナンスタイプ | 料金 |
|------------------|------|
| コンパクション - オブジェクト† | $0.004/1,000オブジェクト処理 |
| 圧縮 - データ処理量 | $0.05/GB処理 |

† テーブルバケットに保存されているオブジェクトが自動コンパクション用に処理されると、コンパクション料金が発生します。S3テーブルバケット内の指定されたテーブルで自動圧縮を無効にした場合、これらの料金は発生しません。

#### コンパクション料金

**概要**:
- 小さなオブジェクトをより少ない大きなオブジェクトに定期的に結合する処理
- クエリパフォーマンスを向上させるために実行
- 処理されたオブジェクト数に基づいて課金

**課金タイミング**:
- デフォルトで有効
- テーブルバケットに保存されているオブジェクトが自動コンパクション用に処理されたとき

**無効化**:
- 指定されたテーブルで自動圧縮を無効にすることが可能
- 無効にした場合、コンパクション料金は発生しない

#### 圧縮料金

**概要**:
- コンパクション中に処理されたデータ量に基づいて課金
- 処理されたGB数に基づく課金

**課金対象**:
- コンパクション中に処理されたオブジェクトのバイト数

**コスト削減のポイント**:
- メンテナンス設定の最適化
- 必要に応じて自動圧縮の無効化
- 適切なファイルサイズの設定（初期から大きなファイルを作成）

**重要な注意**:
- 自動メンテナンスは、長期的にはストレージコストを削減する効果があります
- 短期的にはメンテナンス操作自体にコストがかかります
- トータルコストでの評価が重要です

### データ転送料金

#### リージョン内転送

**概要**:
- 同一AWSリージョン内でのデータ転送

**料金**:
- **S3 Tables ↔ AWS分析サービス（同一リージョン）**: 通常無料
- **S3 Tables ↔ EC2（同一リージョン）**: 通常無料

#### リージョン間転送

**概要**:
- 異なるAWSリージョン間でのデータ転送

**料金**:
- **送信元リージョンからの転送**: GB単位で課金
- **受信先リージョンへの転送**: 通常無料

**コスト削減のポイント**:
- Table Bucketとクエリエンジンを同一リージョンに配置
- リージョン間転送の最小化

#### インターネット転送

**概要**:
- AWSからインターネットへのデータ転送

**料金**:
- **インターネットへの転送**: GB単位で課金（最初の1GBは無料）
- **インターネットからの転送**: 無料

**コスト削減のポイント**:
- VPCエンドポイントの使用
- AWS Direct Connectの活用
- データ転送の最小化

## 料金例

### ETLジョブによる日次更新のユースケース

**シナリオ**:
- 毎日ETLジョブを使用して、さまざまな構造化ソースと非構造化ソースからのデータを前処理
- テーブルバケット内のApache Icebergテーブルを1日1回更新
- 平均オブジェクトサイズが5MBの1,000個の新しいデータファイルを作成
- 平均オブジェクトサイズが10KBのメタデータファイルを3個作成
- テーブルのユーザーはデータセットに対して頻繁にクエリを実行（1か月あたり500,000回のGETリクエスト）
- クエリのパフォーマンスを最適化するため、S3 Tablesで自動圧縮を有効化
- 月末のテーブルのサイズは1TB、オブジェクトの平均サイズは100MB
- リージョン: 米国西部（オレゴン）

**料金計算**:

#### 1. S3 Tables ストレージ料金

```yaml
ストレージ量: 1 TB = 1,024 GB
料金: 最初の50TB/月 = $0.0265/GB

計算: 1,024 GB × $0.0265/GB = $27.14
```

#### 2. S3 Tables PUT リクエスト料金

```yaml
1日あたりのPUTリクエスト: 1,000データファイル + 3メタデータファイル = 1,003リクエスト
月間PUTリクエスト: 1,003リクエスト/日 × 30日 = 30,090リクエスト
料金: $0.005/1,000リクエスト

計算: 30,090リクエスト × $0.005/1,000リクエスト = $0.15
```

#### 3. S3 Tables GET リクエスト料金

```yaml
月間GETリクエスト: 500,000リクエスト
料金: $0.0004/1,000リクエスト

計算: 500,000リクエスト × $0.0004/1,000リクエスト = $0.20
```

#### 4. S3 Tables オブジェクトモニタリング料金

```yaml
テーブルサイズ: 1 TB = 1,048,576 MB
平均オブジェクトサイズ: 100 MB
オブジェクト数: 1,048,576 MB ÷ 100 MB = 10,486オブジェクト
料金: $0.025/1,000オブジェクト

計算: 10,486オブジェクト × $0.025/1,000オブジェクト = $0.26
```

#### 5. S3 Tables 圧縮料金

**コンパクション - オブジェクト処理料金**:
```yaml
月間追加データファイル: 1,000ファイル/日 × 30日 = 30,000ファイル
料金: $0.004/1,000オブジェクト

計算: 30,000ファイル × $0.004/1,000オブジェクト = $0.12
```

**圧縮 - データ処理料金**:
```yaml
処理データ量: 30,000ファイル × 5 MB = 150,000 MB = 146.48 GB
料金: $0.05/GB処理

計算: 146.48 GB × $0.05/GB = $7.32
```

#### 合計料金

| 料金項目 | 金額（USD） |
|---------|------------|
| S3 Tables ストレージ料金 | $27.14 |
| S3 Tables PUT リクエスト料金 | $0.15 |
| S3 Tables GET リクエスト料金 | $0.20 |
| S3 Tables オブジェクトモニタリング料金 | $0.26 |
| S3 Tables 圧縮 - オブジェクト処理料金 | $0.12 |
| S3 Tables 圧縮 - データ処理料金 | $7.32 |
| **合計** | **$35.19** |

### 料金の内訳分析

**コスト構成比**:
- ストレージ料金: 77.1% ($27.14)
- 圧縮料金: 21.1% ($7.44)
- その他（リクエスト、モニタリング）: 1.8% ($0.61)

**コスト削減のポイント**:
1. **ストレージコスト**: 最大の割合を占めるため、自動メンテナンスによる未参照ファイル削除が重要
2. **圧縮コスト**: 初期から大きなファイルを作成することで、コンパクション処理を削減可能
3. **リクエストコスト**: 比較的小さいが、バッチ処理の活用で削減可能

## コスト最適化戦略

### タグによるコスト配分

#### コスト配分タグの活用

**概要**:
- Table BucketとTableにタグを付けることで、プロジェクトやチームごとにコストを追跡可能

**タグの種類**:

| タグタイプ | 説明 | 例 |
|-----------|------|-----|
| **AWS生成タグ** | AWSが自動的に作成・適用するタグ | `createdBy` |
| **ユーザー定義タグ** | ユーザーが作成・適用するタグ | `project:analytics`, `team:data-science`, `environment:production` |

**タグの制限**:
- **タグセットあたりの最大タグ数**: 50個
- **タグキーの長さ**: 1〜128 Unicode文字
- **タグ値の長さ**: 0〜256 Unicode文字
- **キーの一意性**: タグセット内でキーは一意である必要がある

**設定手順**:

1. **タグの作成と適用**
   - Table BucketまたはTableにタグを追加
   - S3コンソール、AWS CLI、またはAPIを使用

2. **コスト配分タグの有効化**
   - AWS Billing and Cost Managementコンソールでタグを有効化
   - 有効化後、コストレポートにタグ列が表示される

3. **コストレポートの確認**
   - Cost Explorerでタグごとにコストをフィルタリング
   - コスト配分レポートでタグごとのコストを確認

**ベストプラクティス**:
- 一貫したタグ命名規則の使用
- 必須タグの定義（project、environment、owner等）
- タグポリシーの実装（AWS Organizations）
- 定期的なタグの監査

**コスト配分の例**:

```text
プロジェクトごとのコスト配分:
- project:analytics → $1,000/月
- project:ml-training → $2,500/月
- project:reporting → $500/月

環境ごとのコスト配分:
- environment:production → $3,000/月
- environment:staging → $500/月
- environment:development → $500/月
```

### 自動メンテナンスによるストレージ削減

#### コンパクション

**効果**:
- 小さなファイルを大きなファイルに統合
- ファイル数の削減によるメタデータストレージの削減
- クエリパフォーマンスの向上

**コスト削減の仕組み**:
- メタデータファイルサイズの削減
- ストレージI/Oの削減
- クエリ実行時間の短縮（Athenaの場合、スキャンデータ量に基づく課金）

**推奨設定**:
- 適切なコンパクション戦略の選択（Auto、Binpack、Sort、Z-order）
- ターゲットファイルサイズの最適化（デフォルト512MB）

#### スナップショット管理

**効果**:
- 古いスナップショットの自動削除
- 不要なスナップショットメタデータの削減

**コスト削減の仕組み**:
- スナップショットストレージの削減
- メタデータストレージの削減

**推奨設定**:
- 適切な保持ポリシーの設定
  - `minimumSnapshots`: 最小スナップショット数（デフォルト1）
  - `maximumSnapshotAge`: 最大保持期間（デフォルト5日）

#### 未参照ファイル削除

**効果**:
- スナップショットから参照されていないファイルの自動削除
- 不要なデータファイルの削除

**コスト削減の仕組み**:
- データストレージの削減
- ストレージコストの直接的な削減

**推奨設定**:
- 適切な削除タイミングの設定
  - `unreferencedDays`: 未参照ファイルの保持期間（デフォルト3日）
  - `nonCurrentDays`: 非現行バージョンの保持期間（デフォルト10日）

### 同一リージョン配置

#### リージョン内配置のメリット

**コスト削減**:
- リージョン間データ転送料金の回避
- レイテンシの削減によるクエリ実行時間の短縮

**推奨構成**:
```text
同一リージョン内:
- Table Bucket
- Amazon Athena
- Amazon Redshift
- Amazon EMR
- AWS Glue
- その他の分析サービス
```

**注意事項**:
- マルチリージョン構成が必要な場合は、データレプリケーション戦略を検討
- ディザスタリカバリ要件との バランス

### 適切なパーティション設計

#### パーティショニングによるコスト削減

**効果**:
- クエリ時のスキャンデータ量の削減
- Athenaの場合、スキャンデータ量に基づく課金のため直接的なコスト削減

**推奨設計**:
- 低カーディナリティのパーティションキーの選択
- クエリパターンに基づくパーティション設計
- 過剰なパーティション分割の回避

**コスト削減の例**:
```yaml
パーティションなし:
- スキャンデータ量: 1TB
- Athenaコスト: $5.00

日付パーティション（1日分のクエリ）:
- スキャンデータ量: 3GB
- Athenaコスト: $0.015
- コスト削減: 99.7%
```

## 料金の見積もり

### AWS Pricing Calculatorの使用

**手順**:
1. [AWS Pricing Calculator](https://calculator.aws)にアクセス
2. Amazon S3またはS3 Tablesを検索
3. 以下の情報を入力:
   - リージョン
   - ストレージ量（GB）
   - リクエスト数（月間）
   - データ転送量（GB）
4. 月額料金の見積もりを取得

### 見積もりに必要な情報

**ストレージ**:
- 予想されるデータ量（GB）
- スナップショット保持期間
- メタデータ量の推定

**リクエスト**:
- 月間のテーブル操作数
- 月間のデータアクセス数
- クエリ頻度

**データ転送**:
- リージョン間転送量
- インターネット転送量

**メンテナンス**:
- コンパクション頻度
- スナップショット管理頻度

## 他のストレージオプションとのコスト比較

### S3 Tables vs S3汎用バケット（セルフマネージドIceberg）

| コスト要素 | S3 Tables | S3汎用バケット（セルフマネージドIceberg） |
|-----------|-----------|----------------------------------------|
| **ストレージ料金** | Table Bucket料金 | S3 Standard料金 |
| **リクエスト料金** | S3 Tables API料金 | S3 API料金 |
| **メンテナンスコスト** | 自動メンテナンス料金（含まれる可能性） | 手動実装コスト（EMR、Glue等） |
| **運用コスト** | 低（自動化） | 高（手動管理） |
| **初期コスト** | なし | 実装コスト |
| **長期コスト** | 自動最適化によるストレージ削減 | 手動最適化が必要 |

### コスト比較の考慮事項

**S3 Tablesが有利な場合**:
- 運用負荷を最小化したい
- 自動メンテナンスによるコスト削減を期待
- 初期実装コストを抑えたい

**S3汎用バケットが有利な場合**:
- 完全なカスタマイズ性が必要
- 既存のメンテナンスパイプラインがある
- ストレージコストを最小化したい（S3 Intelligent-Tiering等の活用）
