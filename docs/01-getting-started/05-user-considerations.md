## 概要

このドキュメントでは、Amazon S3 Tablesを使用する際の運用上の考慮事項、ベストプラクティス、および注意点について説明します。

## 削除操作に関する考慮事項

### マネジメントコンソールからの削除制限

**重要**: Amazon S3 Tablesのリソース（Table Bucket、Namespace、Table）は、現時点でAWSマネジメントコンソールから削除できません。

#### 削除方法

以下のいずれかの方法を使用する必要があります：

1. **AWS CLI**
2. **AWS SDK**
3. **REST API**
4. **統合クエリエンジン**（テーブルのみ）

### Table Bucketの削除

#### 前提条件
- Table Bucketを削除する前に、**すべてのNamespaceとTableを削除する必要があります**
- 削除は永久的で、元に戻すことはできません
- すべてのデータと設定が完全に失われます

#### 必要な権限
- `s3tables:DeleteTableBucket`

#### AWS CLI例

```bash
aws s3tables delete-table-bucket \
    --region us-east-2 \
    --table-bucket-arn arn:aws:s3tables:us-east-1:111122223333:bucket/amzn-s3-demo-bucket1
```

#### 注意事項
- バケット削除は永久的で取り消し不可
- すべてのデータと設定が完全に失われます
- 削除前に重要なデータをバックアップまたはレプリケートしてください

### Tableの削除

#### 削除方法

##### 1. AWS CLI

```bash
aws s3tables delete-table \
    --table-bucket-arn arn:aws:s3tables:us-east-1:111122223333:bucket/amzn-s3-demo-table-bucket \
    --namespace example_namespace \
    --name example_table
```

##### 2. Apache Spark（DROP TABLE PURGE）

```sql
DROP TABLE [IF EXISTS] s3tablesbucket.example_namespace.example_table PURGE
```

#### 重要な制限事項

**`purge=false`非サポート**:
- S3 Tablesは`DROP TABLE`操作で`purge=false`をサポートしていません
- 一部のApache Sparkバージョンは、`DROP TABLE PURGE`コマンドを実行しても常にこのフラグを`false`に設定します
- **回避策**:
  1. `purge=true`で`DROP TABLE`を再試行
  2. S3 Tables `DeleteTable` REST API操作を使用

#### 注意事項
- テーブル削除は永久的で取り消し不可
- すべてのデータと設定が完全に削除されます
- 削除前に重要なデータをバックアップまたはレプリケートしてください

## ネットワークとアクセスに関する考慮事項

### HTTPS必須

- **HTTPリクエストは非サポート**
- HTTPリクエストは自動的にHTTPSへリダイレクトされます
- すべてのクライアントアプリケーションはHTTPSを使用する必要があります

### IPv6制限

- **限定的サポート**: テーブルストレージエンドポイント経由のオブジェクトレベルアクションのみ
- **非サポート**: テーブルレベルおよびバケットレベルのアクション
- Dual-stackエンドポイントを使用する場合は、この制限に注意してください

### エンドポイント

- **標準エンドポイント**: `s3tables.aws-region.api.aws`
- **Dual-stackエンドポイント**: IPv4とIPv6の両方をサポート（制限あり）
- **AWS PrivateLink**: VPC内からのプライベートアクセスをサポート

## セキュリティに関する考慮事項

### Public Access（パブリックアクセス）

- **常に無効**: パブリックアクセスは常にブロックされます
- **変更不可**: ユーザーはこの設定を変更できません
- **理由**: セキュリティベストプラクティスに基づく設計

### Presigned URLs

- **非サポート**: テーブルに関連付けられたオブジェクトへのアクセスに署名付きURLは使用できません
- **代替手段**: IAMロールやSTS一時認証情報を使用してください

### AWS Signature Version

- **必須**: REST APIを使用する際は、AWS Signature Version 4を使用する必要があります

### ポリシーサイズ制限

- **最大サイズ**: 20KB
- **影響**: 複雑なポリシーを作成する際は、サイズ制限に注意が必要です
- **ベストプラクティス**: 可能な限りシンプルなポリシーを作成し、必要に応じて複数のポリシーに分割してください

## メンテナンスに関する考慮事項

### 自動メンテナンスの影響

#### コンパクション

- **自動実行**: コンパクションは自動スケジュールで実行されます
- **料金**: コンパクション実行時に料金が発生します
- **無効化**: 料金を回避したい場合は、`PutTableMaintenanceConfiguration` APIで手動で無効化できます

#### 同時実行制御

- **楽観的同時実行制御**: Apache Icebergは楽観的同時実行制御モデルを使用
- **競合の可能性**: ユーザートランザクションとコンパクショントランザクションが競合する可能性があります
- **推奨事項**: パイプラインに再試行ロジックを実装してください

#### スナップショット管理

- **自動削除**: 期限切れスナップショットは自動的に削除されます
- **タイムトラベルクエリ**: 削除されたスナップショットに対してタイムトラベルクエリは実行できません
- **注意**: ブランチ/タグベースの保持ポリシーを設定すると、自動スナップショット管理が無効化されます

### メンテナンス設定のベストプラクティス

#### コンパクション設定

- **targetFileSizeMB**: デフォルト512MB、最小64MB
- **推奨**: ワークロードの特性に応じて調整してください
- **考慮事項**: ファイルサイズが小さすぎるとメタデータオーバーヘッドが増加します

#### スナップショット保持

- **minimumSnapshots**: デフォルト1、最小1
- **maximumSnapshotAge**: デフォルト120時間、最小1時間
- **推奨**: タイムトラベルクエリの要件に応じて設定してください
- **注意**: 保持期間を長くするとストレージコストが増加します

#### 未参照ファイル削除

- **unreferencedDays**: デフォルト3日、最小1日
- **nonCurrentDays**: デフォルト10日、最小1日
- **推奨**: 安全マージンを考慮して設定してください
- **注意**: 短すぎる設定は、実行中のトランザクションに影響を与える可能性があります

## タグ管理に関する考慮事項

### タグサポート（2025年11月6日追加）

#### 利用可能な機能

- **コスト配分**: タグを使用してストレージコストを追跡できます
- **ABAC**: 属性ベースアクセス制御でタグを使用できます
- **追加料金なし**: タグの使用に追加料金はかかりません（標準のS3 APIリクエスト料金のみ）

#### Lake Formationとの統合

- **重要**: Lake Formationを使用する場合、IAMロールに同じプリンシパルタグを付与する必要があります
- **対象ロール**: LakeFormationDataAccessRoleなど
- **理由**: タグベースアクセス制御ポリシーが正しく機能するために必要です

#### タグのベストプラクティス

1. **一貫した命名規則**: 組織全体で一貫したタグキーと値を使用してください
2. **必須タグの定義**: `project`, `environment`, `owner`, `cost-center`などの必須タグを定義してください
3. **タグガバナンス**: `aws:TagKeys`条件キーを使用して、許可されるタグを制限してください
4. **自動化**: Infrastructure as Codeを使用してタグを自動的に適用してください

## サービスクォータに関する考慮事項

### デフォルトクォータ

| リソース | デフォルト値 | 調整可能 |
|---------|------------|---------|
| Table Buckets | 10 per Region | ✓ |
| Namespaces | 10,000 per table bucket | ✓ |
| Tables | 10,000 per table bucket | ✓ |

### クォータ管理のベストプラクティス

1. **事前計画**: 大規模なデプロイメントの前にクォータ要件を評価してください
2. **早期申請**: クォータ引き上げには時間がかかる場合があるため、早めに申請してください
3. **モニタリング**: CloudWatchメトリクスを使用してリソース使用状況を監視してください
4. **アラート**: クォータに近づいたときに通知を受け取るようにアラートを設定してください

## データ型とファイル形式に関する考慮事項

### コンパクションのサポート

#### サポートされるファイル形式
- Apache Parquet（デフォルト出力）
- Apache Avro
- Apache ORC

#### 非サポート項目
- **データ型**: `Fixed`データ型
- **圧縮タイプ**: `brotli`, `lz4`

#### 出力形式の変更

デフォルトではParquet形式で出力されますが、以下のように変更できます：

```sql
-- Avro形式で出力
ALTER TABLE example_table SET TBLPROPERTIES ('write.format.default'='avro');

-- ORC形式で出力
ALTER TABLE example_table SET TBLPROPERTIES ('write.format.default'='orc');
```

## 運用のベストプラクティス

### 1. バックアップとリカバリ

- **定期的なバックアップ**: 重要なデータは定期的にバックアップしてください
- **スナップショット活用**: Icebergスナップショット機能を活用してください
- **クロスリージョンレプリケーション**: 災害復旧のためにクロスリージョンレプリケーションを検討してください

### 2. モニタリングとアラート

- **CloudTrail**: すべてのAPI呼び出しをログに記録してください
- **CloudWatch**: メトリクスとログを監視してください
- **アラート**: 異常な動作や制限値への接近を検知するアラートを設定してください

### 3. コスト最適化

- **タグによるコスト配分**: タグを使用してコストを追跡してください
- **メンテナンス設定の最適化**: 不要なメンテナンスを無効化してください
- **ストレージクラスの検討**: アクセスパターンに応じて適切なストレージクラスを選択してください

### 4. セキュリティ

- **最小権限の原則**: 必要最小限の権限のみを付与してください
- **暗号化**: SSE-KMSを使用してデータを暗号化してください
- **VPCエンドポイント**: プライベートアクセスにはVPCエンドポイントを使用してください
- **監査**: CloudTrailログを定期的にレビューしてください

### 5. パフォーマンス

- **パーティション戦略**: 適切なパーティション戦略を設計してください
- **コンパクション設定**: ワークロードに応じてコンパクション設定を調整してください
- **同一リージョン配置**: コンピューティングリソースとテーブルバケットを同一リージョンに配置してください

## トラブルシューティング

### よくある問題と解決策

#### 1. テーブル削除の失敗

**問題**: `DROP TABLE`コマンドが失敗する

**原因**: `purge=false`が設定されている

**解決策**:
- `DROP TABLE PURGE`を使用する
- または、`DeleteTable` REST APIを使用する

#### 2. コンパクションの競合

**問題**: トランザクションが頻繁に失敗する

**原因**: ユーザートランザクションとコンパクショントランザクションの競合

**解決策**:
- パイプラインに再試行ロジックを実装する
- コンパクションスケジュールを調整する
- 必要に応じてコンパクションを一時的に無効化する

#### 3. スナップショット管理の無効化

**問題**: スナップショットが自動削除されない

**原因**: ブランチ/タグベースの保持ポリシーまたは`metadata.json`での設定

**解決策**:
- Icebergテーブルからブランチ/タグベースの保持ポリシーを削除する
- `metadata.json`の設定を削除する
- または、手動でスナップショットを削除する
